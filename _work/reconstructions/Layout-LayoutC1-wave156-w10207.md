## 3. Fresh adjacent-swap sweep on the w10106 base (new)

Because the w10009 file could not be brought down to 1,986, a fresh
exhaustive adjacent-statement swap sweep was run on the w10106 base
(266 top-level statements; 193 swaps compile; each compiled with the
exact NDK r18b clang 7.0.2 flags, mini-linked with gold, stripped, and
measured with `align_diff`).  The best strict improvement is:

* **swap `field_0xc8` and `oreLabelYOffset`** (source lines 84/85):
  raw **5,837 -> 5,822** (-15), aligned **1,986 -> 1,984** (-2),
  size 7,072.

This is the landed change.  It is a plausible source order: the original's
`0xc0..0xcc` SLP group is emitted as `vst1.32 {9,11,5,253}` at `0xc0`;
putting `oreLabelYOffset` before `field_0xc8` lets the scheduler keep the
`0xc4/0xc8` pair in the shared tail while the `0xc0` store moves to the
late `0x294` block, matching the original's late `0xc0` store.

Second- and third-round adjacent sweeps from this base (each 193 swaps)
found further raw reductions at the cost of aligned:

| variant | size | raw | aligned |
|---|---:|---:|---:|
| w10106 base | 7,072 | 5,837 | 1,986 |
| **swap c8/oreLabel (landed)** | **7,072** | **5,822** | **1,984** |
| + swap 0x114/0x238 (F) | 7,072 | 5,806 | 1,995 |
| + swap 0x114/0x238 + choiceWindowTitleHeight/0x284 | 7,072 | **5,805** | 1,989 |
| + swap 0x2f4/0x2f8 | 7,072 | 5,798 | 2,024 |
| + swap 0x19c/0x18c | 7,072 | 5,864 | **1,982** |

The best raw at size 7,072 is **5,798** (aligned 2,024); the best aligned
is **1,982** (raw 5,864).  The landed swap is the only measured variant
that improves *both* metrics.
