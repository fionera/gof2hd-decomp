## Ground truth (original, image base 0x10000)

Frame `sub sp,#224`. Stack slots (decimal):

```
#64 timeLeft lo   #68 timeLeft hi   #72 fireImageIndex  #76 secondaryKind
#80 mining        #84 savedColor    #88 stack guard    #92 iPad
#96 dividerOffset #100 &Globals::layout   #104 this     #108 Globals::globals
#112 dt           #116 ego          #120 Canvas        #220 canary
```

Ours (baseline) uses the same 224-byte frame but a different rotation:

```
#64 timeLeft lo   #68 timeLeft hi   #72 pad_          #76 fireImageIndex
#80 secondaryKind #84 mining        #88 guard         #92 iPad
#96 dividerOffset #100 savedColor   #104 &Globals::layout  #108 Globals
#112 dt           #116 ego          #120 Canvas       #220 canary
```

The original has **no `pad_` local** and **does spill `this`**: `str r5,[sp,#104]`
at `0x163e04`, reloaded at `0x163e1e`, `0x163e26`, `0x163e2e` (shield image
selection), `0x164040` (gamma block), `0x1640ec` (rocket block) and `0x16413e`
(damage indicators). Ours keeps `this` in `r5` throughout.

## Two semantic differences in the current source

1. `src/game/ui/Hud.cpp` shield branch contains `canvas->SetColor(savedColor);`.
   The original has **no** `SetColor` there — it draws shield/armour/gamma with
   the white set at `0x163dfc`. This is the extra `SetColorEj` (ours 25, original 23).
2. `int pad_ = this->field_0x470;` plus `if (pad_ != 0) Globals::Canvas->SetColor(savedColor);`
   before the autopilot block. The original reads `field_0x470` **only** in the
   decrement block (`0x163d5a`/`0x163d6a`) and has no guard at `0x164ff8`.
   `pad_` is a reconstruction anchor.

Removing both (and using `unsigned int *shieldImage = &this->shieldFrameImage`
with a `*shieldImage` load, which matches the original's `add r0,r5,#676/680;
ldr r1,[r0]` shape) makes the function **9240 B, frame 216**, and the slot order
becomes exactly the original's minus the `this` slot:

```
#60 timeLeft lo #64 timeLeft hi #68 fireImageIndex #72 secondaryKind
#76 mining #80 savedColor #84 guard #88 iPad #92 dividerOffset
#96 Globals #100 &Globals::layout #104 dt #108 ego #112 Canvas
```

So adding one 4-byte `this` spill would rotate every slot into the original
position (`savedColor` #84, `dividerOffset` #96, `&layout` #100, `this` #104,
`Globals` #108, `dt` #112, `ego` #116, `Canvas` #120). The 92-byte size gap is
mostly the redundant `this` store/reloads plus the different register
allocation they induce.

## What was tried to force the `this` spill

All measured on top of "remove `pad_` + shield `SetColor`" (`68.1%, 9240 B`):

| construct | result |

| `Hud *self = this;` (top / after `savedColor` / before shield), used in shield image selection, gamma, rocket, damage | always coalesced; 9240 B |
| `Hud *self = (Hud *)this;` / `(Hud *)((char *)this)` / `Hud &self = *this;` | coalesced; 9240 B |
| `Hud **selfPtr = &self; (*selfPtr)->...` | coalesced; 9240 B |
| `Hud **volatile selfPtr = &self;` | 9624 B, 44.2% |
| `Hud *volatile self = this;` (all uses) | 9380 B, 16.8% |
| `Hud *volatile self` (gamma only) | 9676 B, 48.6% |
| pointer `armorY`/`armorBarY` (`unsigned short *`) | 9232 B, 61.7% |
| hoisted `Layout *layout = Globals::layout;` | 9208 B, 67.6% |
| hoisted `PaintCanvas *canvas` at function scope | 9228 B, 58.7% |

| `int armorY` instead of `unsigned short armorY` | 9332 B, 88.8% |

The greedy allocator output (`-mllvm -print-machineinstrs`) shows `this`
(`%2925`) is never spilled: it is assigned `$r5` and every source copy of it
(`%2926`) is coalesced back to `$r5`. The original's redundant
store-then-reload is a live-range split the current source shape does not
provoke.

## Most important remaining root cause

The original's **`this` spill at `[sp,#104]`** (a redundant store/reload across
the shield/armour/gamma/rocket region, reusing the `GetImage2DWidth` scratch
slot). It is the only missing stack slot: with it the frame is 224 and the
whole slot rotation, `savedColor` placement, `dividerOffset` register (`sl`),
and the `this`-in-`r6` gamma-block shape fall into place. Without it the frame
is 216 and every middle-region load/store offset is 4 bytes off. The source
construct that makes clang 7.0.2 at `-Oz` split `this`'s live range here has not
been identified; all natural copies of `this` are copy-propagated away.
