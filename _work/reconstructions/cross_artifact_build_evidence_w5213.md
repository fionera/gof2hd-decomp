# Cross-artifact build evidence (w5213)

Status: research note, 2026-11-04. Worktree `/home/debian/GalaxyOnFire2/wt/w5213`,
branch `wave104-w5213`, base `8c5fd3646`. Scratch: `/dev/shm/w5213` only.
**No source or build-flag change is landed.** Every experiment was measured with the
official verifier and reverted; the note is the deliverable. The canonical gate is
unchanged.

## 0. Bottom line

* The Android library is **NDK r18b, clang 7.0.2, gold 1.12, API 16,
  armeabi-v7a, Thumb-2, NEON, softfp, libc++**, compiled with `-Oz -g` and
  `-std=c++11 -fPIC -frtti -fstack-protector-strong -ffunction-sections
  -funwind-tables`, linked with a single plain gold link and post-processed by
  GNU `strip --strip-all` plus the `.shstrtab` reorder.
* The iOS IPA and Windows binary are **not Android flag oracles**. iOS 1.1.4 is
  Apple clang 1.0 / Xcode 4.5 / iphoneos6.0, unoptimized (`-O0`-style), libstdc++.6,
  SJLj exceptions. iOS 1.0.5 is Xcode 4.0 / GCC 4.2. Windows is x86 MSVC 2010 and
  packed (`.text` entropy exactly 8.000). They confirm source/TU/ABI facts and
  source shape, not Android codegen flags.
* The source-file dumps contain **no compiler or assembler flags**. They are
  symbol/contributor lists: Xcode DerivedData paths, architecture, source paths and
  per-TU symbols. They confirm TU membership and emitted function order only.
* The KiritoJPK mod rebuild is a second compilation of the same source family
  (NDK r14 / clang 3.8 / `-O2` / system libstdc++). It confirms the 24 residual
  functions are present in the same relative order, but its codegen is too
  different to be a byte oracle.
* **No strict improvement exists at this tree state.** The six new A/B variants
  (`-fno-plt`, `-mtune=cortex-a8`, `-fmerge-constants`,
  `-fno-delete-null-pointer-checks`, `-fno-vectorize`, C++-only `-std=gnu++11`)
  are all gate-neutral at 4500 / 4500 / 4524. No baseline update was made.

## 2. What transfers to Android, what does not, and what is unknown

### 2.1 Positively proven

1. **Android toolchain identity.** `.comment`, `.note.android.ident`,
   `.note.gnu.gold-version` and `.ARM.attributes` prove NDK r18b / clang 7.0.2 /
   gold 1.12 / API 16 / ARMv7-A / Thumb-2 / VFPv3 / NEONv1 / softfp.
2. **`-Oz`.** Whole-tree A/B: `-Oz` 4500 vs `-Os` 1263, `-O2` 1168, `-O3` 1167;
   per-TU 184/192 vs `-O2`, 191/192 vs `-O1`, 192/192 vs `-O0`.
3. **`-g` is codegen-relevant.** `-g0`/`-g1`/`-gline-tables-only` drop the gate to
   2069; `-g`/`-g2`/`-g3` are identical. The mechanism is a `DBG_VALUE` pinning an
   entry-block argument copy against PostRA machine sinking.
4. **`-fstack-protector-strong`.** The original has 787 `__stack_chk_fail` call
   sites; basic `-fstack-protector` gives 88, `-fstack-protector-all` gives 83
   byte-exact.
5. **`-ffunction-sections`.** The original `.ARM.exidx` has 193 `CANTUNWIND`
   entries sharing a target with a real entry, gold's sentinel for each object's
   empty plain `.text` section; removing the flag drops byte_exact to 1345.
6. **`-funwind-tables`.** `.ARM.exidx` has 3,566 entries; filtered removal drops
   byte_exact to 2878.
7. **`-fdata-sections` was not used.** `.rodata` is `0x41b67` without it and
   `0x41a07` with it; byte_exact 4500 vs 4311.
8. **`-std=c++11`, not c++14.** `Material::Material` is 276 B vs 272 B under
   c++14; full c++14 drops byte_exact to 1512.
9. **`-stdlib=libc++`, RTTI and exceptions.** The original imports/emits the
   libc++abi set, `_ZTI`/`_ZTS`/`_ZTV`, `__cxa_throw`, `__cxa_begin_catch`,
   `_Unwind_Resume`; `-fno-rtti` drops to 1701 and `-fno-exceptions` fails to
   build.
10. **Default visibility.** `-fvisibility=hidden` gives 57; `-fvisibility=protected`
    gives 1345; `-fvisibility-inlines-hidden` gives 1278 and 141 missing.
11. **Single plain gold link.** `-shared -soname libgof2hdaa.so --build-id -z now
    --exclude-libs=libgcc.a`, no `-s`, no section-ordering file, no
    `--unresolved-symbols`, no `--version-script`, no
    `--allow-multiple-definition`. The original's build-id is the SHA-1 of the
    unstripped gold output with the 20-byte descriptor zeroed.
12. **Post-link GNU strip + `.shstrtab` reorder.** The APK library is the original
    plus the 288-byte raw-bfd `.shstrtab`/`sh_name` difference; the ground truth
    is the reordered version.
13. **Source/TU membership.** The iOS 1.1.19 dump assigns all 20 unique residual
    functions to the same TUs as our tree and confirms the emitted order for the
    sampled TUs.
14. **Cross-platform ABI.** iOS and Android both use ARMv7 Thumb-2, NEON and
    softfp; `Vector::Vector(float,float,float)` takes x/y/z in r1/r2/r3 on both.
15. **The 24 residuals are source-shape, not a missing global flag.** The
    KiritoJPK rebuild preserves all 24 in the same relative order; the iOS
    siblings confirm source structure for 3 of them; the whole-`.text` census
    attributes every instruction-pattern delta to the 24 bodies.
