## Hypothesis tested: literal-pool word order and tbh switch lowering

Tools written this pass (tracked in `_work/reconstructions/w7727/`; the two disassembly
inputs `orig_an.txt`/`ours_an.txt` are regenerated by `analyze.py`):

* `analyze.py` — dumps every pc-relative literal-pool load (address, target, raw word,
  float decode) and every `tbh`/`tbb` table with its decoded targets.
* `tbh2.py` — prints, for each `tbh`, the number of entries and a "default vs distinct
  target" pattern (`.` = the most common target, `A/B/...` = distinct targets in address
  order). Useful for spotting a changed case grouping.
* `tbhm.py` — prints the `cmp` that bounds each `tbh` and the five preceding instructions.
* `seq2.py` — classifies every pool word (`A`=data address, `C`=code address, `F:<float>`,
  `I:<int>`, `Z`=0) and diffs the two ordered sequences.
* `score.py` — re-runs `verify.py`'s exact normalisation/reconcile/score for one symbol.

### Why the mission-0 table is 4..15 in ours

Original mission-0 dispatch (`0x137e84`..`0x138fd8`):

```
0x137e90  msg2->isOver() && m_nState == 0   -> state 0
0x1383fe  cmp r1,#2 ; bgt 0x1389c8          -> states 1,2
0x1389c8  cmp r1,#4 ; beq 0x138d2a          -> state 4
0x1389ce  cmp r1,#3 ; bne 0x138fd8          -> state 3
0x138fd8  cmp r1,#5 ; bne 0x139b1a          -> state 5
0x139b1a  subs r0,r1,#6 ; cmp r0,#9         -> tbh states 6..15
```

i.e. the source if/else-if order is **state 4, state 3, state 5**, and the final
`else` is the `switch` over states 6..15. Our source is **state 3, state 5, state 4,
else switch**. Because state 4 is the last *pure equality* `else if` before the
`switch`, clang's SimplifyCFG folds it into the switch, extending the `tbh` range to
4..15. The original's last equality (state 5) is compound
(`m_nState == 5 && msg->isOver()`), so it is **not** folded and the table stays 6..15.

### Literal-pool order

`seq2.py` shows the pool word sequences are 74.8% identical; the first real divergence
is at pool word 23:

```
ORIG 23..27: 5000.0 | 30000.0 | 3.1415927 | 10000.0 | 10000.0
OURS 23..27: 10000.0 | 10000.0 | <addr> | <addr> | <addr> ... 5000.0 | 30000.0 | 3.1415927
```

The `5000/30000/pi` triple is the **mission-5** body
(`setPosition(x+5000, y, z+30000); rotate(0, pi, 0)`); `10000/10000` is the
**mission-0x51** arrival body. In the original the mission-5 body is emitted at
`0x13813c`, *before* the mission-0x51 body at `0x1381ca` (the shared tail at `0x137f7c`
falls through to the mission-5 check at `0x13812a`, while mission 0x51 is a forward
branch taken from the `else` of mission 1). In our source the mission-5/26/50/51 chain
is an `else if` **of the shared tail**, so those bodies are emitted after the
mission-0x51/0x4e bodies. That is the pool-order root cause.

## Experiments (all semantic-preserving reorders; measured with `score.py`)

| variant | size | pct | mission-0 tbh |
|---|---:|---:|---|
| base (3,5,4 / state-5 compound) | 57232 | 59.2 | 4..15 |
| mission-0 order 4,3,5, state-5 **nested** `if` | 57232 | 55.4 | 3..15 |
| mission-0 order 4,3,5, state-5 **compound** | 57256 | 56.8 | **6..15** |
| mission-0 order 3,4,5, state-5 compound | 57256 | 56.8 | **6..15** |
| mission-0 order 3,4,5, state-5 nested `if` | 57232 | 55.4 | 3..15 |
| swap mission-26 / mission-5 branches | 57232 | 59.1 | 4..15 |
| mission-5 `else if` -> plain `if` (after shared tail) | 57484 | 57.7 | 4..15 |
| move mission-5 branch ahead of mission-0x51 (pool order) | 57276 | 40.1 | 4..15 |

Conclusions:

* The 4,3,5 order is the faithful branch order and does produce the original's
  6..15 `tbh`, **but it costs +24 B** (57256) and the fuzzy score falls to 56.8.
* The nested-`if` form keeps 57232 B exactly but lets clang fold state 3 instead
  (3..15), and the score falls to 55.4.
* No variant improves the fuzzy score; the base layout is already the closest.
* Moving mission-5 ahead of mission-0x51 to force the original pool order collapses the
  score to 40.1 (+44 B): the mission-5 body placement is a consequence of the shared-tail
  fall-through, not of the source check order.
* The mission-5 `else if` -> `if` change is a genuine semantic fix (the original runs
  the mission-5 check even when `m_bStartSequence != 0`, because `0x137f82 beq
  0x13812a` skips only the tail *body*, not the check), but it costs **+252 B** and
  scores 57.7, so it needs a large companion before it can land.
